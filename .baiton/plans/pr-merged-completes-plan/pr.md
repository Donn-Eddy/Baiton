Until now it stayed in **Active** even after every recorded request had been merged, so users had to mark it `done` by hand. This change derives completion from the providers instead: when every recorded request reads merged, the plan is listed under **Completed** without writing the document.\n\nThe derivation is read-only and fail-soft. `status`, `pr`, `prs`, `approved_rev` and the approval hash stay byte-identical, no commit/branch/working-tree change happens, and a window reload re-derives the same grouping. It never rejects: CLI failures, bad URLs and unrecognised output all resolve `'unknown'`.\n- `gh` runs `pr view <n> --repo <host/owner/repo> --json state`; `glab` runs `mr view <iid> --repo <group/project> --output json`. Editing the URL set re-arms the check; non-`pr` plans and plans with no URL are never queried.\n\n### `src/activation/commands.ts` — wiring\n- New `prToolForRoot` mirrors `submitPrForSlug`'s provider resolution (`pr.tool` → `selectProvider` → `resolveProviderExecutable` over the configured remote) and yields `undefined` on any failure.\n- `prsMergedForPlan` resolves the repo per URL (primary, or the `prs` key's repo via repo configs), calls `stateByUrl`, and applies `planPrsMerged`.
