# OVERVIEW

Add a dedicated, silent `Baiton: API` output channel that records one entry per FAILED outbound API call the extension makes, and route every call site through one host-free logging unit so a new call site has exactly one obvious place to log.

**Logging unit — `src/orchestrator/apiLog.ts` (new, no `vscode` import).** It exports:
- `ApiFailureKind = 'http-status' | 'timeout' | 'connection' | 'abort' | 'malformed-response' | 'refused'` (the six failure classes in the requirements).
- `ApiFailureEntry { surface: string; operation: string; target?: string; kind: ApiFailureKind; status?: number; message: string; bodyExcerpt?: string }` — `surface` is a provider id, `'copilot'`, a `CatalogSourceId`, or an agent id; `operation` is a short verb noun such as `'completion'` or `'model list'`; `target` is the URL or model id when known.
- `ApiLogSink = (line: string) => void` — the injectable write path, threaded exactly like the existing catalog `log:` callback.
- `ApiLog { failure(entry: ApiFailureEntry): void }` and `createApiLog(sink: ApiLogSink, now?: () => string): ApiLog` — `failure` redacts, formats one line (`[<iso ts>] <surface> <operation> <kind>[ HTTP <status>][ <target>] — <message>[ | body: <excerpt>]`) and writes it. Successful calls never touch it.
- `noopApiLog: ApiLog` — the default when a caller injects nothing, so every `apiLog?:` option is optional and existing constructors/tests compile unchanged.
- `redactSecrets(text: string): string` — the single shared helper: scrubs `Bearer <token>`, `authorization: <value>` (any casing), `api[-_]?key[=:] <value>`, `x-api-key`, and long opaque tokens matching `sk-…`/`key-…` shapes; `failure()` applies it to `message`, `target` and `bodyExcerpt` unconditionally, so redaction cannot be forgotten at a call site.
- `BODY_EXCERPT_MAX = 500` and `excerpt(body: string): string` — bounded response-body excerpt, newline-collapsed.
The unit is exported from `src/orchestrator/index.ts` like its siblings.

**Channel ownership — `Surface` (`src/activation/surface.ts`).** `Surface` creates a second `vscode.OutputChannel` named `API` (constant `API_CHANNEL_NAME`) alongside the `Baiton` channel, exposes it as `apiOutputChannel` for disposal, exposes `apiLog: ApiLog` built by `createApiLog((line) => apiChannel.appendLine(line))`, and offers `logApiFailure(entry)` as a convenience. Nothing in the write path calls `show()`, `reveal` or a notification: the log is silent. The constructor keeps its optional injected `channel` and gains an optional injected `apiChannel` so tests can pass fakes. `src/extension.ts` pushes `surface.apiOutputChannel` onto `context.subscriptions` right after `surface.outputChannel`. Existing `log`/`info`/`warn`/`error`/`reportDispatchError` are untouched.

**Threading (the `log:` callback pattern).** Every outbound call site accepts an optional `apiLog?: ApiLog`, defaulting to `noopApiLog`:
- `OpenAiModelClient` via `ModelClientConfig.apiLog` — logs non-2xx (`http-status`, status, URL, body excerpt), connect timeout (`timeout`), socket/connection and response-stream errors (`connection`), aborts (`abort`), and a non-JSON non-streaming body (`malformed-response`). `surface` is the provider id supplied through a new `ModelClientConfig.surfaceId?: string` (defaults to `'openai'`), `operation` is `'completion'`, `target` is the completions URL. `MissingConfigError` is raised before any request and is NOT a call failure, so it is not logged.
- `CopilotModelClient` via `CopilotClientConfig.apiLog` — logs `NoPermissions`/`Blocked` as `refused`, other `sendRequest`/`selectChatModels` throws as `connection`, and a mid-stream abort as `abort`; `surface` `'copilot'`, `operation` `'completion'`, `target` the model id. A `NotFound` model resolves to `MissingConfigError` as today and is not logged.
- `ProviderRouter` (`src/activation/providerRouter.ts`) gains `ProviderRouterConfig.apiLog?` and passes it (plus the provider id as `surfaceId`) into every client it builds; `src/activation/commands.ts` passes `surface.apiLog`.
- `fetchModelsDev` via `FetchModelsDevOptions.apiLog` — logs unavailable fetch and request failure (`connection`), timeout (`timeout`), non-2xx (`http-status`), invalid JSON and an unparseable feed (`malformed-response`); `surface` `'models.dev'`, `operation` `'model list'`, `target` the feed URL. Its `Result` contract is unchanged.
- `DiscoveryContext` (`src/adapter/adapter.ts`) gains `readonly apiLog?: ApiLog`. `ModelDiscoveryService` gains `ModelDiscoveryOptions.apiLog?`, forwards it to `fetchModelsDev` (its default `fetchFeed`) and into every adapter's `ctx`, and logs adapter-level outcomes itself in `refreshAgent` (timeout → `timeout`, thrown/rejected → `connection`, resolved `undefined` → `malformed-response` with message `'<agent> model discovery returned no models'`) with `surface` the agent id and `operation` `'model list'`. `refreshFeed` logs only the failures it produced itself (its own timeout race and a thrown fetcher), never re-logging a `Result` error `fetchModelsDev` already logged. `src/extension.ts` passes `surface.apiLog` to the service.
- Adapters with an HTTP leg use `ctx.apiLog`: `OpencodeAdapter.discoverFromApi` logs `/api/model` non-2xx, request failure/timeout and unparseable JSON with the request URL as `target`; `ClaudeAdapter.discoverModels` forwards `ctx.apiLog` to its `fetchFeed` fallback call so the feed leg logs through `fetchModelsDev`. Codex and antigravity make no HTTP call; their CLI/app-server failures are covered by the service-level entry.
- `CatalogStore.applyResult` (`src/orchestrator/modelCatalog.ts`) is deliberately NOT a logging point: the discovery service is the one choke point for catalog sources, which keeps one failure from producing a store-level duplicate. A doc comment records this so a future contributor does not add one.

**Constraints honoured.** No request protocol or semantics change; no new runtime dependency; the `Baiton` channel output and `Surface` notification behaviour are unchanged; no `vscode` import enters `src/orchestrator/` or `src/adapter/`. Tests are mocha under `test/`: the logging unit (redaction incl. a property-style sweep that no `Bearer`/`authorization` value survives, formatting, excerpt bounding, noop), `Surface` against fake channels (silent, separate channel, disposal handle), and one induced failure per covered call site asserting exactly one entry reaches an injected sink and that a successful call produces none. `npm run compile`, `npm run lint` and `npm test` must stay green after every todo.
