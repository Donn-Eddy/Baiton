  "body": "## What changed\n\nAdds a dedicated, silent API-failure log: one entry per **failed** outbound API call the extension makes, written to a second output channel named `API`, separate from the existing `Baiton` channel.\n\n- **`src/orchestrator/apiLog.ts` (new, host-free).** Exports `ApiFailureKind` (`http-status`, `timeout`, `connection`, `abort`, `malformed-response`, `refused`), `ApiFailureEntry`, `ApiLog`, `ApiLogSink`, `createApiLog(sink, now?)`, `noopApiLog`, `redactSecrets`, `excerpt` and `BODY_EXCERPT_MAX = 500`. `failure()` redacts `message`, `target` and `bodyExcerpt` **unconditionally** (Bearer tokens, `authorization`, `api[-_]?key`, `x-api-key`, long `sk-`/`key-` tokens), then formats a single line: `[<iso ts>] <surface> <operation> <kind>[ HTTP <status>][ <target>] — <message>[ | body: <excerpt>]`. Sink and formatter failures are swallowed so logging can never change a call's outcome. Exported from the `src/orchestrator` barrel.\n- **`Surface` (`src/activation/surface.ts`) owns the channel.** New `API_CHANNEL_NAME = 'API'`, `apiOutputChannel`, `apiLog` (built with `createApiLog((line) => apiChannel.appendLine(line))`) and `logApiFailure(entry)`. The constructor takes an optional injected `apiChannel` for tests. Nothing on the write path calls `show()`, `reveal` or a notification — the log is silent. `src/extension.ts` pushes `surface.apiOutputChannel` onto `context.subscriptions` right after `surface.outputChannel`.\n- **Threaded like the existing catalog `log:` callback.** Every call site takes an optional `apiLog?: ApiLog` defaulting to `noopApiLog`, so existing constructors and tests compile unchanged:\n  - `OpenAiModelClient` (`ModelClientConfig.apiLog` + new `surfaceId?`, default `'openai'`, operation `completion`, target the completions URL): non-2xx with status and body excerpt, connect timeout, connection/response-stream error, abort, and a non-JSON non-streaming body. Each rejection logs exactly once, guarded by the existing `settled` check. `MissingConfigError` is raised before any request and is not a call failure, so it is not logged.\n  - `CopilotModelClient` (`CopilotClientConfig.apiLog`, surface `copilot`, target the model id): `NoPermissions`/`Blocked` as `refused`, other `vscode.lm` throws as `connection`, a mid-stream abort as `abort`. `NotFound`/missing/stale models still resolve to `MissingConfigError` and are not logged. Inline chat error messages are unchanged.\n  - `fetchModelsDev` (`FetchModelsDevOptions.apiLog`, surface `models.dev`, operation `model list`, target the feed URL): a local `fail()` helper writes one entry and returns the same `err` string for unavailable fetch, request failure, timeout, non-2xx, invalid JSON and an unparseable feed. The `Result` contract is unchanged.\n  - `DiscoveryContext.apiLog` and `ModelDiscoveryOptions.apiLog`: `ModelDiscoveryService` forwards it to its default `fetchFeed` and into every adapter's `ctx`, and logs adapter-level outcomes in `refreshAgent` (timeout → `timeout`, thrown/rejected → `connection`, `undefined` → `malformed-response`) with the agent id as surface. `refreshFeed` logs only failures it produced itself; a `Result` error already logged by `fetchModelsDev` is never re-logged (a generation-guarded gate drops a late entry for a fetch the service's race already reported as a timeout). `src/extension.ts` passes `surface.apiLog`.\n  - Adapters with an HTTP leg: `OpencodeAdapter.discoverFromApi` logs `/api/model` non-2xx (with status and body excerpt), request failure, timeout and unparseable JSON with the request URL as target, distinguishing its own timeout from a caller abort; `ClaudeAdapter` forwards `ctx.apiLog` to its `fetchFeed` fallback so the feed leg logs once via `fetchModelsDev`. Codex and antigravity make no HTTP call — their CLI/app-server failures are covered by the service-level entry.\n- **`CatalogStore.applyResult` is deliberately not a logging point** (documented in a doc comment) so one catalog failure cannot produce a store-level duplicate.\n\nNo request protocol or semantics change, no new runtime dependency, the `Baiton` channel output and `Surface` notification behaviour are unchanged, and no `vscode` import enters `src/orchestrator/` or `src/adapter/`.\n\n## Why\n\nPreviously a failed provider call, Copilot call or model-discovery fetch left only scattered evidence: inline chat error text and best-effort lines in the shared `Baiton` channel, which are mixed with ordinary activity and never mention the endpoint that failed. Debugging a provider outage meant guessing which call failed from an error string.\n\nThe new channel answers that directly: which surface (`openai`/provider id, `copilot`, `models.dev`, `opencode`, agent ids), which operation (`completion`, `model list`), which target (URL or model id), which failure class, the HTTP status and a bounded body excerpt — on one greppable line, one per failure, with secrets scrubbed by construction. Routing every call site through a single host-free unit means a new outbound call has exactly one obvious place to log, and because redaction happens inside `failure()` it cannot be forgotten at a call site. The channel is silent: diagnosing a failure should never interrupt the user with a notification or steal focus.\n\n## How it was verified\n\n- `npm run compile`, `npm run lint` and `npm test` after **every** todo.
