1. Probe OpenCode for a real OpenCode Go usage route (no quota spent, no secret printed)

   Run these probes yourself before writing code and keep the abridged outputs for the file header and the README. Ground rules: never start a model turn (no `opencode run <prompt>`, no `--command`, no POST to a chat/completions endpoint); never echo a credential (read it into a shell variable, print only key names and types, e.g. `jq 'to_entries|map({provider:.key,type:.value.type,fields:(.value|keys)})'`); run everything from a scratch dir, not the workspace. Probe in this order, which is also the order the reader will try:
   (a) CLI command: `opencode --version`; `opencode --help`; `--help` of every subcommand that could matter (`stats`, `auth`, `providers`/`auth list`, `account`, `models`, anything named usage/quota/limit/billing/go). Note `opencode stats` (if present) aggregates LOCAL session tokens/cost: it is not remaining usage, misses other machines, and turning it into 'remaining' against documented Go limits would be extrapolation, so it must NOT become the route (record it as probed, unusable, with the reason).
   (b) CLI server: start `opencode serve --hostname 127.0.0.1 --port 0` (same argv as OPENCODE_SERVE_ARGS in src/adapter/opencode.ts), learn the URL from its banner, then `curl -s $URL/doc | jq '.paths|keys'` (OpenAPI) and grep the paths and schemas for usage|quota|limit|subscription|billing|account|rate. GET every candidate route and also `/provider` and `/config/providers`; check whether the `opencode-go` provider/models carry account usage. Model `limit` fields (context/output token limits) are NOT usage — do not mistake them. Kill the server afterwards.
   (c) CLI files: list `~/.local/share/opencode`, `~/.local/state/opencode`, `~/.cache/opencode`, `~/.config/opencode` (and $XDG_* overrides); grep (keys only) for quota/usage/limit/remaining/reset outside per-message session content; a SQLite db, if any, inspect with `sqlite3 .tables`/schema only.
   (d) Provider endpoint fallback: identify the stored login in `~/.local/share/opencode/auth.json` (expected entry `opencode` and/or `opencode-go`, `{type:'api', key}` or `{type:'oauth', access, refresh, expires}`). Read https://opencode.ai/docs/go (and /docs/zen) with WebFetch for any documented usage/limits endpoint. With the key in a variable, try only read-only GETs: the documented usage endpoint if one exists, and `curl -sS -D - -o /dev/null -H "Authorization: Bearer $K" https://opencode.ai/zen/go/v1/models` to see whether response headers carry x-ratelimit-*/usage figures. Record HTTP status and the field names/shape, not values tied to the account.
   Decision: the established route is the first of (a)→(b)→(c) that returns provider-given used/remaining figures for the Go limits (e.g. 5-hour / weekly / monthly); (d) is wired only as a trusted-only fallback and only if it actually returned such figures. If nothing returns them, the established outcome is 'no workable route' and the reader reports unavailable with that reason — that is an acceptable, spec-compliant result. Save sanitised samples (any id/email/key replaced with placeholders) as fixtures in step 4.

## Risks

- OpenCode may expose no OpenCode Go usage at all (Go limits may only be visible on the opencode.ai console). Then the correct outcome is an unavailable reader with an honest, probe-backed reason — do not fill the row from `opencode stats` local spend or documented dollar limits; that would be an extrapolated figure.
- Probing can spend quota or leak secrets: never run a model prompt or POST a completion, and never print auth.json values or the Authorization header (use jq on keys only, curl -o /dev/null -D -).
- Model `limit` fields from /provider or `opencode models --verbose` are context/output token limits, not account usage — easy to misread as quota.
- The usage tool id is 'opencode-go' while the adapter AgentId is 'opencode'; using 'opencode' makes UsageService reject the reading as invalid.
- A provider endpoint found by probing may be undocumented and change; keep it last, trusted-only, and parse totally so a shape change yields unavailable, not a crash.
- `opencode serve` started by the reader must be disposed on every path, including timeout/abort, or a background process leaks (the service aborts the signal on timeout — listen for it).
- redactSecrets masks any 32+ char token-like run; keep window ids/labels short so they are not mangled, and do not put URLs with long ids in `detail`.
- Name collisions in the src/usage barrel (export *) with other readers' helpers — prefix every export.
