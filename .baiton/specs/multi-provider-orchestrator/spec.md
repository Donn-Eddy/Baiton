# OVERVIEW

Give the Baiton chat orchestrator first-class support for five inference backends — OpenCode Go, Google AI Studio (Gemini's OpenAI-compatible endpoint), Mistral AI, a generic OpenAI-compatible endpoint, and GitHub Copilot through the in-process `vscode.lm` API — with one API key per provider and a grouped Provider & Model dropdown in the Chat view.

Today `src/orchestrator/modelClient.ts` holds a single `OpenAiModelClient` that reads one endpoint/model from settings and one secret (`baiton.orchestrator.apiKey`, written by `src/activation/setApiKey.ts`); `buildModelClient` in `src/activation/commands.ts` constructs it once and hands the same instance to the `ChatController` and to the Auto-mode gate (`decideAsk`). The webview protocol (`src/orchestrator/webviewProtocol.ts`, mirrored byte-for-behaviour in `media/protocol.js` and guarded by `test/webviewProtocol.mirror.test.ts`) has no notion of a provider; the empty state shows endpoint + model and offers a single Set API Key action.

The design keeps every existing seam and adds a provider layer around it:

1. A host-free provider catalog (`src/orchestrator/providers.ts`) is the single source of truth: provider ids (`copilot`, `google`, `opencode`, `mistral`, `openai`), display labels and dropdown order, default base URLs (Google `https://generativelanguage.googleapis.com/v1beta/openai/`, Mistral `https://api.mistral.ai/v1`, OpenCode Go's documented base), the SecretStorage key of each keyed provider (`baiton.orchestrator.key.<provider>`), the built-in model lists (Gemini 2.5 family, Mistral large/codestral/etc., OpenCode Go's supported models) and a validated `ModelSelection { provider, model }` type plus its `workspaceState` key. Copilot needs no key; `openai` keeps using the existing `baiton.orchestrator.endpoint` / `baiton.orchestrator.model` settings as the "OpenAI / Custom" entry, so nothing users already configured breaks. The legacy `baiton.orchestrator.apiKey` secret is migrated once into the `openai` slot.

2. `OpenAiModelClient` grows two injected hooks instead of being forked per provider: `extraHeaders(req)` (OpenCode Go's `User-Agent: baiton/<version>` and `x-opencode-session: <uuid>`) and a wire `dialect` that shapes messages before serialisation. The Gemini dialect is the tool-chaining fix: an assistant `tool_calls` turn must not carry an empty `content` string (omit it / send `null`), every `tool` message must carry only `role`, `tool_call_id`, `content` and follow its assistant turn directly, and argument strings must be valid JSON objects — the shapes Gemini's OpenAI translation rejects or silently truncates today, which is why the loop stalls until a fresh user message arrives. A `CompletionRequest` also gains an optional `sessionId` (the chat session id) that the tool loop and `ChatController` thread through, so the OpenCode header is stable for a whole conversation.

3. A new `CopilotModelClient` (`src/orchestrator/copilotClient.ts`) implements the same `ModelClient` interface over `vscode.lm`: it maps `ChatMessage`s to `LanguageModelChatMessage`s (assistant tool calls → `LanguageModelToolCallPart`, tool results → `LanguageModelToolResultPart` inside a user message), `ToolSpec`s to `LanguageModelChatTool`s, streams text parts to `onDelta`, collects tool-call parts into `CompletionResult.tool_calls`, honours the abort signal through a `CancellationTokenSource`, and maps a missing model / consent failure to the existing error classes so the controller's inline-error path works unchanged.

4. A host-side `ProviderRouter` (`src/activation/providerRouter.ts`) replaces `buildModelClient`: it owns one client per provider, reads keys from `context.secrets`, reports which providers are enabled and why not, enumerates models (Copilot via `vscode.lm.selectChatModels({ vendor: 'copilot' })`, the rest from the catalog / settings), persists the active selection, and itself implements `ModelClient` by delegating each `complete` to the active provider — so the `ChatController`, the tool loop and the Auto-mode evaluator all switch together the moment the user picks a new model, with no change to transcripts on disk.

5. The protocol gains `setProviders` (host→webview: ordered groups with `enabled`, an optional disabled `reason`, their models and the active selection) and `selectModel` (webview→host); `chat.html`/`chat.js` render it as a `<select>` with one `<optgroup>` per provider, disabled groups for providers without a key (with a "Set API key…" affordance), and the empty state shows provider + model instead of endpoint + model. Per-provider key management is one command, `baiton.setProviderApiKey` (quick-pick the provider, then set or clear with a masked input); `baiton.setOrchestratorApiKey` stays registered as an alias so existing key bindings and the README keep working.

Every todo below is a self-contained, testable unit; host-free cores land first with unit tests, `vscode`-bound glue follows and is tested through the existing `test/fixtures/vscodeFake.mjs` loader where practical. Acceptance: separate keys per provider; grouped dropdown with disabled providers; Gemini multi-step tool calls chain without user intervention; OpenCode requests always carry the session header and User-Agent; Copilot runs in-window with full tool calling; switching providers never loses history or corrupts a transcript.
