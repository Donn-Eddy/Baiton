## Risks

- Making the CLI primary changes what the DEFAULT-constructed adapter does on a developer machine that has opencode installed: any test that builds an OpencodeAdapter without injecting `runModelsCli` would now shell out to the real CLI. test/modelSelectorRefresh.test.ts already stubs `runModelsCli: async () => undefined` (line ~321), so it stays on the API path, but re-check for any other construction site before finishing.
- The verbose-block scanner must ignore braces inside string values, or a model whose `name`/`description` contains `{` or `}` swallows the following entries. The fixture's `Weird {model} name` case exists to catch this; an unterminated block must also degrade to a plain entry and consume to EOF rather than loop.
- `--verbose` is unknown to older opencode builds; depending on the build it may error (runner resolves `undefined`, so the API fallback still runs) or print the bare listing (the verbose parser must produce the same ids as `opencodeModelsFromCliOutput` — the parity test is what guards this).
- Dropping `{ efforts: [...OPENCODE_EFFORTS] }` from `capabilitiesFromEntries` makes the capability-level `efforts` non-empty for the first time for opencode; the webview still renders free text while the union is empty, and later todos handle the select-plus-Other… rendering. `OPENCODE_EFFORTS` itself must stay `[]` so the curated fallback is unchanged.
- `efforts: []` and a missing `efforts` key are NOT interchangeable — a `{}`-variants model must omit the key so a manually typed `--variant` for it stays reachable through the agent-level union. Emitting an empty array instead would suppress the whole effort list for that model downstream.
- The ~50 KB verbose output and the ~1.5 s runtime share the single discovery budget with the fallback; a slow CLI can leave no budget for `/api/model`, which is acceptable (the refresh then keeps the last known-good list) but must not throw or hang.

## Acceptance

- `opencode models --verbose` is the primary source: with a CLI run that yields at least one `provider/model` entry, `discoverModels` returns those entries and the injected `startServer` and `fetchModels` seams are never called.
- `opencodeModelsFromVerboseOutput` on test/fixtures/opencodeModelsVerbose.sample.txt yields the fixture ids in listing order with `provider` set, labels from `name` (omitted when `name` equals the bare model id), `efforts` equal to each model's `variants` keys in order, no `efforts` key for a `{}`-variants model, a plain `{ id, provider }` entry for the unparseable block and for the detail-less trailing id, no `defaultEffort` anywhere, first-occurrence-wins de-duplication, and `[]` for empty input.
- On a bare listing the verbose parser yields exactly the same ids as `opencodeModelsFromCliOutput`, and `opencodeModelsFromCliOutput` is still exported with its existing tests passing.
- `/api/model` is requested only when the CLI is unavailable, rejects, times out, or yields no entry; on that path the entries are ids and labels only and the capability-level `efforts` is `[]`.
- No request is ever made to `/provider` or `/config/providers`; every URL the fetch seam sees ends with `/api/model`.
- Both sources unusable resolves `undefined` (never `OPENCODE_MODELS`/`OPENCODE_EFFORTS`); an already-aborted signal starts no process and makes no request; an abort mid-flight resolves `undefined`; a server this call started is disposed exactly once and a `serverBaseUrl`/`OPENCODE_SERVER` server is never killed; `discoverModels` never rejects.
- The capability-level `efforts` is the ordered union of the entries' own levels, and the result still carries no `source`/`stale`/`staleReason`/`fetchedAt`/`modelLink` own keys.
- `OPENCODE_MODELS_ARGS` is `['models', '--verbose']` and the default runner spawns exactly that argv; `OPENCODE_MODELS`/`OPENCODE_EFFORTS` and the launch/attach argv (`--variant <effort>`, no flag for an empty effort, never `--variant default`) are unchanged — `launch()`/`attach()` stay byte-identical with and without discovery options.
- The whole test suite passes, including test/adapter.opencode.test.ts and test/modelSelectorRefresh.test.ts, with no test depending on a real `opencode` binary; lint and typecheck are clean.
- README's discovery section describes the CLI-first precedence, the `variants`-keys effort source, the ids-only `/api/model` fallback, the never-requested key-bearing endpoints, and the read-only fields in the privacy bullet.
