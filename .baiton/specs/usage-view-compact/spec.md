# OVERVIEW

Make the Usage view (`baiton.usageView`, spec first-party-usage) more compact by reflowing what it already draws and moving the per-card detail line into the status badge's hover hint. Only media/usage.js, media/usage.html, test/usageView.media.test.ts and README.md change. Nothing changes in src/usage/**, src/activation/usageView*, the webview protocol (`ready`/`refresh` out, `readings`/`state` in), refresh/coalescing/polling, the CSP, dependencies, TOOL_ORDER, or the data shown. The existing rules still hold: no inline handlers or style attributes in the HTML, colors only from VS Code theme variables, and DOM text written only through textContent (plus plain attribute setters: `title`, `tabindex`, `aria-label`).

Current shape (media/usage.js `buildCard`): each window is a `.window` box with stacked divs: `.window-label` (label plus ` · Baiton-derived` when derived), `.window-scope`, the `.bar` progressbar (only when `hasBar`), `.window-figure`, and `.window-reset` (with `title` = absolute time). After the windows the card draws `.reason` and then `.source-line` (`cardView().sourceLine`: for ok/stale `<mechanism> — <detail> · Provider-reported|Baiton-derived · read <age>`, for unavailable `Tried: <mechanism>`). The header holds `.badge.<status>` with text from BADGE_TEXT, an optional `.badge.derived` 'Baiton-derived' badge, and 'Refreshing…'.

Target layout:
1. Window row. Each window draws one `.window-row` flex container with a left group, `.window-head` (holding `.window-label`, then `.window-figure` inline beside it), and, only when `resetText` is non-empty, a right cell `.window-reset` with the same text as today (formatReset is unchanged) and `title` = resetAbsolute when present. With no reset no element is appended, so no space is reserved. The row uses `display:flex; flex-wrap:wrap; align-items:baseline; justify-content:space-between; gap:…`. `.window-reset` gets `margin-left:auto; white-space:nowrap`. The head may wrap internally and must not be squeezed, so at activity-bar width the reset drops onto its own line instead of overflowing. Under the row, `.window-scope` (only when scopeText is set) keeps its own dimmed line, and the `.bar` progressbar (only when hasBar) sits on its own line under the scope, with its aria attributes unchanged. The ` · Baiton-derived` suffix on a derived window's label stays visible. For tests, expose a pure helper `windowRow(w)` (also on `window.baitonUsageView`) that takes a `windowView()` result and returns `{ label, figure, reset, resetTitle }`, where `reset` is '' when there is no reset. `buildCard` builds the row from it.
2. Badge hint. `cardView()` gains `badgeHint`. For ok/stale rows it is the existing source line string. For unavailable rows it is `Tried: <mechanism label>`, or '' when the mechanism is unknown. For loading rows it is ''. `sourceLine` stays as an alias holding the same string, so the existing mirror tests remain valid. When `badgeHint` is non-empty, `buildCard` sets `title`, `aria-label` (same text) and `tabindex="0"` on the OK/Stale/Unavailable `.badge.<status>` span. The loading badge gets none of these. `.source-line` is no longer appended to the card body. Stale cards keep `Showing data from <age>` and the `Last read failed: <reason>` reason line, and unavailable cards keep their reason. Baiton-derived provenance stays visible in the body through the header `.badge.derived` badge and the per-window label suffix. It must never be shown only on hover. Add a theme-colored keyboard focus ring for the badge (`.badge:focus-visible { outline: 1px solid var(--vscode-focusBorder); }` or similar) and a `cursor: help` affordance. Remove the now-unused `.source-line` CSS selector (or leave it harmless).

Tests (node test runner, pure-helper mirror loaded from usage.js; no DOM): add assertions for `windowRow` (figure next to label, reset text and title, empty reset when resetsAt is absent, raw-number figure when there is no percent) and for `badgeHint` on ok, stale, unavailable and loading rows, keeping every existing assertion, including the `formatReset` cases. Also assert that usage.js no longer appends `source-line` to the card and that it sets `tabindex`/`aria-label`/`title` on the badge, using a source-text check like the existing unsafe-sink test. Docs: update the README Usage view bullet (around README.md:55-65) and the intro paragraph of '### Usage view (per-tool probe findings)' (README.md:1048-1050) so they say that each window is one row (label and figure on the left, reset on the right, which wraps when narrow) with the scope and bar below, and that the source/provenance/read-time line is now the status badge's hover/focus hint while the Baiton-derived marker stays visible. Finish line: `npm run compile`, `npm run lint` and `npm test` pass.
