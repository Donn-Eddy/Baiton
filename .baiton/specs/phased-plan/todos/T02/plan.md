## Risks

- The conversation-scope discriminator `ConversationKind { kind: 'spec' }` looks like the mode but is a separate concept. Renaming it here would sprawl into the systemPrompt, sessionStore, subAgent and chatController work that later todos own, so leave it.
- media/chat.js and media/protocol.js are plain JS and the compiler cannot check them. If the id 'plan' is missed there, the mode select falls back to an empty value or misreports the pinned mode; test/chatView.mode.test.ts and test/webviewProtocol.reducer.test.ts are the guard.
- A persisted workspaceState value 'spec' and a run manifest whose composerMode is 'spec' would otherwise silently become DEFAULT_MODE or make the manifest unreadable. Both must go through toRunMode.
- Journal start records with stage 'spec-draft' from before the rename would be dropped by the isStage check and could confuse recovery. The toStage legacy mapping covers this.
- The repository's own .baiton/config.json and user configs still use 'spec-writer'. loadConfig must map it at read time and must never rewrite the file. The config panel may save a document with plan-writer while the old spec-writer key is still present; plan-writer wins, so that is acceptable.
- Keep this todo to ids. Do not change the plan-draft result shape (overview/todos), persistencePathForStage's 'spec.md', the draft_spec tool name, the specDraft.ts file name or storage paths. Later todos own those, and changing them here would break tests out of scope.
- Opencode and other adapters build agent names from roleProfile().agentName, so any adapter test that snapshots 'baiton-spec-writer' must be updated with the rest.
