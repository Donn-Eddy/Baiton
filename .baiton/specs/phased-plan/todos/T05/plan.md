## Risks

- `resolveDocument` would send a draft into `specs/` when a legacy `specs/<slug>/` directory exists without spec.md (it prefers an existing legacy directory over a non-existent plans one), so planDraft must use `locationFor(baitonDir, slug, 'plan')` explicitly. Using the resolver here silently breaks the 'new writes go only under plans/' rule.
- The orchestrator tool is still `draft_spec` with a `requirements` argument, and `DraftSpecRequest`/`DraftSpecSeam` in seams.ts are unchanged. PlanDraftRequest keeps the `requirements` field so the seam passes straight through. Renaming the field now would ripple into seams.ts, controlTools.ts and their tests, which belong to the orchestrator phase.
- `services.git.commit` runs `git add -A`. The draft commit therefore stages the whole working tree, as the old draft did. The new commit message prefix is `plan(<slug>):`, but the other spec-write tools still commit `spec(<slug>):` until the orchestrator phase. That inconsistency is expected and temporary.
- The plan-writer's prose could itself contain a line reading exactly `# PHASES` (or `# TODOS`), which would move the parser's section boundary or kind detection. The instruction tells the writer not to include one. If needed, the executor may defensively demote such lines in renderPlan (e.g. prefix with `#` to make `## PHASES` is NOT enough since isHeader matches any level — instead indent the line by one space or wrap it). Treat this as optional hardening, not required.
- Making `endstate`/`changes`/`constraints` `minLength: 1` means a writer that leaves a section empty produces an invalid result and the run keeps waiting for a rewrite (existing invalid-result behaviour). This is intended, but the roundtrip property arbitrary must generate non-empty strings or it will fail.
- Removing `renderSpec`/`RenderSpecTodo` from specWriteTools.ts requires confirming that no other src or test file imports them. Today only specDraft.ts does, and the identically named test helpers are local functions.
- Several tests outside the brief's file list reference the old API (test/integration.sub-agent-chats.test.ts, test/engine.briefWatcher.test.ts and test/schema.roundtrip.property.test.ts), and so do comments in engineFacade.ts, runPipeline.ts and runStore.ts. They must change in the same phase to keep compile and the suite green.

- A draft refuses with duplicate-slug when either `.baiton/plans/<slug>/plan.md` or the legacy `.baiton/specs/<slug>/spec.md` exists. A legacy `specs/<slug>/` directory without spec.md does not block it, and does not redirect it.
